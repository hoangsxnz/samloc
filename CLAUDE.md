# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Sâm Lốc Online" — Vietnamese card game played in the browser. One Cloudflare Worker serves everything: the Svelte 5 SPA (static assets), `/api/*` (Hono: auth, lobby, history on D1), and `/ws/:code` (one `RoomDO` Durable Object per room, WebSocket Hibernation API). UI is Vietnamese-only and landscape-only.

## Workspaces

pnpm 10 workspaces, Node >= 24. Use `pnpm`, never npm/yarn.

- `packages/rules` (`@samloc/rules`) — pure TS rules engine. Zero deps, JSON-serializable state. Source of truth for all game rules.
- `apps/worker` (`@samloc/worker`) — Hono API + `RoomDO`. Also the home of shared wire types.
- `apps/web` (`@samloc/web`) — Vite + Svelte 5 (runes) + Tailwind v4 SPA, hash router.

`@samloc/rules` is consumed as raw TypeScript source via package `exports` — there is no build step for it. Changing `packages/rules/src` immediately affects both apps.

## Commands

```
pnpm dev          # Vite + @cloudflare/vite-plugin: SPA, Worker, DO and D1 all in one process
pnpm typecheck    # pnpm -r typecheck
pnpm test         # pnpm -r test (vitest; rules + worker only)
pnpm build        # vite build
pnpm deploy       # build, then wrangler deploy
```

Run `pnpm typecheck && pnpm test` after changing code, before reporting the work done.

Single test file: `pnpm --filter @samloc/rules exec vitest run tests/cards.test.ts`.

`apps/web` has no tests — verify UI changes with `pnpm dev` and visual inspection.

## Local setup

After `pnpm install`, apply D1 migrations to local state (note the non-default state path):

```
pnpm --filter @samloc/worker exec wrangler d1 migrations apply samloc-db --local --persist-to ../web/.wrangler/state
```

Local D1 state lives in `apps/web/.wrangler/state` (gitignored). `worker-configuration.d.ts` is generated by `wrangler types` as part of the worker typecheck; don't commit it.

## Deploy quirk

`vite build` emits a Wrangler config into the web build output (`apps/web/<build-dir>/samloc/wrangler.json`), and the worker's deploy script targets that generated file — not `apps/worker/wrangler.jsonc` directly. Always `pnpm build` before deploying. First-time deploy needs a D1 database created and its `database_id` pasted into `apps/worker/wrangler.jsonc`.

## Architecture

- **The server is the only authority.** `RoomDO` re-validates every client action through `applyGameAction()` from `@samloc/rules`. The client renders only the server-provided `RoomView` — no optimistic updates, no local game-state mutation.
- **Shared wire types live in the worker**, not a shared package: `apps/worker/src/ws-types.ts`, imported by the web app as `import type { ... } from '@samloc/worker/ws-types'`. Keep `ClientMsg`/`ServerMsg`/`RoomView` changes in sync across both sides in the same change.
- Realtime is native WebSocket — no Socket.IO.
- Client socket wrapper: `apps/web/src/lib/ws-client.svelte.ts`.
- Full rule spec: `docs/game-rules.md`. Read it before touching `packages/rules`.

## Code style

There is no ESLint/Prettier/Biome in this repo — conventions are enforced by review, not tooling. Full list in `docs/code-standards.md`; the ones most easily missed:

- Keep source files under 200 lines; split rather than grow.
- kebab-case filenames.
- Any file using runes (`$state`/`$derived`/`$effect`) must use the `.svelte.ts` extension.
- Named exports only, no default exports.
- `import type` for type-only imports (`verbatimModuleSyntax` is on).
- `noUncheckedIndexedAccess` is on — indexing an array yields `T | undefined`; handle it, don't assert it away.
- Never use `{@html}`.
- 2-space indent, LF, final newline (`.editorconfig`).
- No plan/phase/finding references in code comments or commit messages.
